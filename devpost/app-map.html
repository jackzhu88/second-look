What the app is

One static web page that checks a pasted message for scam tactics on the user's own device. Three pieces:

  • The page — index.html + styles.css: text box, sample buttons, empty result areas.
  • The glue — src/app.js: reacts to buttons, calls the rule book, paints results.
  • The rule book — src/rules.js: tactic phrase lists, link checker, verdict, next steps. Pure functions, also used by tests/rules.test.js.

No server, storage of messages, external service or AI API. Only the "Larger text" preference is saved (localStorage['sl-large']).

One action, end to end: "Check this message"

Reference route (3 stops)

A reference route through the real code — not a record of a completed guided tour.

  1. Entry point — src/app.js, search for function runCheck. Reads the text box, shows the "paste a message first" hint if empty, otherwise calls analyze(text).
  2. The decision — src/rules.js, search for export function analyze. Finds links first, then tactic phrases (dropping words that sit inside a link), adds up tactic weights, and picks a level in levelFor. A risky link plus pressure/payment/codes always means "High risk".
  3. What you see — back in src/app.js: renderVerdict, renderHighlighted (builds <mark> elements with text nodes only, so pasted HTML can't run), renderFindings, renderLinks, renderSteps.

A practice to reuse

Write the "must not happen" case as a test before tuning. The PRD's States and Boundaries say a normal message must stay calm. That became the tests normal pharmacy reminder stays low risk and everyday phrases do not trigger in tests/rules.test.js. While writing them, an early pattern for "fine" (as in a penalty) turned out to also match "I'm fine"; it was narrowed to "fined" / "a fine of", and the test now guards against it coming back. On any rules- or prompt-based project, pin down the false positives you refuse to ship as tests first, then tune freely.
